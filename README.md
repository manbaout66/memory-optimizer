# Memory Optimizer（内存优化工具）

一个轻量、开源的 Windows 内存优化小工具，采用与知名 MC 启动器 **PCL** 完全一致的内存优化原理：通过 `SetProcessWorkingSetSizeEx` + NT 内核 `NtSetSystemInformation` 系列调用，将各进程工作集与系统缓存页换出到虚拟内存（页面文件），让任务管理器的可用内存数字立刻上升。

带图形界面（GUI），**PCL 模式深度优化**、实时内存监控、可自定义间隔的定时清理、开机自启、运行日志，全部集成在一个窗口里。

> ⚠️ **重要说明**：本工具的效果是"腾出物理内存"，**并非真正释放内存**——数据会被换到硬盘上的页面文件，程序下次用到时会重新读回（可能短暂卡顿）。深度优化还会清除系统待机缓存（standby），频繁使用会增加硬盘读写。它适合"内存不够用、临时要开大程序"的场景，不适合作为日常提速工具。

## 功能特性

- **一键深度优化（PCL 模式）**：与 PCL 完全一致的 **7 项系统级操作**——清空工作集、刷新文件缓存、刷新修改页、清除待机缓存（standby）、清除低优先级待机页、注册表对账、合并物理内存；自动请求管理员权限（UAC），效果显著（实测可额外腾出 1GB+ 可用内存）
- **实时内存监控**：可用/已用/总内存 + 占用率进度条，每 10 秒自动刷新
- **定时清理**：间隔 **1~720 分钟可自定义**，后台静默运行（轻量清理，无需弹 UAC），支持开机自启，关闭窗口不影响
- **运行日志**：记录每次清理的时间、操作明细、腾出内存
- **现代 UI**：无边框圆角窗口、卡片布局、主色按钮与状态徽章，高分屏 DPI 感知
- **纯脚本零依赖**：仅使用 Windows 自带的 PowerShell 5.1+ 和 .NET 框架，无需安装任何东西

## 快速开始

### 方式一：图形界面（推荐）

```powershell
powershell -ExecutionPolicy Bypass -File .\memory-tool.ps1
```

打开窗口后：

1. 顶部实时显示内存状态；
2. 点 **「一键清理内存」** 执行 PCL 模式深度优化（第一次会弹出 UAC 授权，点"是"即可，之后每次都会请求，因为需要管理员权限操作系统缓存）；
3. 在 **「定时清理」** 区域设置间隔（分钟）→ 点 **「应用间隔」** → 点 **「开启定时清理」**。

> 💡 定时清理使用轻量模式（仅清工作集，免弹窗），适合后台自动运行；想要 PCL 级别的深度效果，手动点「一键清理内存」即可。

### 方式二：命令行

| 参数 | 作用 |
| --- | --- |
| `-silent` | 静默清理一次（轻量），不弹窗 |
| `-deepclean` | PCL 模式深度优化一次（需管理员，会弹 UAC 授权） |
| `-watch [-Minutes 60]` | 后台常驻，按间隔自动清理（默认 30 分钟，合法范围 1~720） |
| `-info` | 弹出当前内存状态 |
| `-schedule [-Minutes 60]` | 开启定时清理（后台进程 + 开机自启项） |
| `-stop` | 关闭定时清理 |

示例：

```powershell
# 后台每 1 小时清理一次（常驻进程）
powershell -ExecutionPolicy Bypass -File .\memory-tool.ps1 -watch -Minutes 60

# 开启开机自启的定时清理，每 15 分钟一次
powershell -ExecutionPolicy Bypass -File .\memory-tool.ps1 -schedule -Minutes 15
```

## 工作原理

### 轻量清理（定时任务用）

```text
进程工作集(物理内存)  --SetProcessWorkingSetSizeEx(handle, -1, -1, 0)-->  换出到页面文件(硬盘)
```

- 对每个可访问的进程，以最小工作集调用 `SetProcessWorkingSetSizeEx`，把不活跃的物理内存页置换到虚拟内存；
- 系统进程及权限受限的进程会被自动跳过，不影响系统稳定；
- 数据没有丢失，仅改变存放位置；程序重新访问时会自动换回（产生一次读盘延迟）。

### 深度优化（一键清理，PCL 模式）

与 PCL 完全一致的实现（移植自 [PCL-CE](https://github.com/PCL-Community/PCL-CE) 的 `MemSwapService`/`MemSwapWorks`，经 ntdll `NtSetSystemInformation` 调用）：

| # | 操作 | NT 系统信息类 | 作用 |
| --- | --- | --- | --- |
| 1 | 清空工作集 | `SystemMemoryListInformation` (80) | 所有进程工作集换出 |
| 2 | 刷新文件缓存 | `SystemFileCacheInformationEx` (81) | 文件缓存页换出 |
| 3 | 刷新修改页 | `SystemMemoryListInformation` (80) | 脏页写回磁盘 |
| 4 | 清除待机缓存 | `SystemMemoryListInformation` (80) | 释放 standby 页（可用内存大幅提升） |
| 5 | 清除低优先级待机页 | `SystemMemoryListInformation` (80) | 同上，低优先级部分 |
| 6 | 注册表对账 | `SystemRegistryReconciliationInformation` (155) | 注册表缓存整理 |
| 7 | 合并物理内存 | `SystemCombinePhysicalMemoryInformation` (130) | 内存页合并压缩 |

深度优化需要管理员权限（`SeProfileSingleProcessPrivilege` + `SeIncreaseQuotaPrivilege`），界面自动请求 UAC 提权。

**优点**：物理内存立刻腾出（实测空闲 25GB 时仍可再腾出 1GB+），适合内存紧张时应急；**代价**：换回时短暂卡顿，机械硬盘更明显；频繁深度清理会增加硬盘读写（对 SSD 有轻微写入损耗）。PCL 官方已弃用此功能（未文档化内核调用），本工具保留供手动使用。

## 安全说明

- **纯本地运行**：不联网、不上传任何数据、不收集统计信息；
- **权限范围**：仅调用系统内存管理 API（`kernel32.dll`/`ntdll.dll`/`advapi32.dll`）、创建/删除启动文件夹快捷方式、按命令行白名单匹配停止自己的后台进程，不做任何其他系统修改；深度优化需要管理员权限且仅在你点击「一键清理内存」时才会请求 UAC，定时清理不会弹窗；
- **输入校验**：定时间隔参数使用强类型 `[int]` 绑定并限制在 1~720 分钟，GUI 控件同样限制范围，非法输入自动回退默认值；
- **进程匹配安全**：停止后台进程时按 `memory-tool.ps1` + `-watch` 命令行特征精确匹配，不会误杀其他进程；
- **深度优化风险提示**：待机缓存（standby）是 Windows 的磁盘缓存，清除后系统会在需要时重新读取（增加少量磁盘 I/O）；请勿设置过短的定时清理频繁深度优化，避免 SSD 写入损耗；
- 如需加固，可自行修改 `Stop-TimerProcess` 或改用计划任务（需要管理员权限）。

## 更新日志

### v1.3.2（2026-09-12）

- **修复**：点击「一键清理内存」或定时清理按钮后偶发弹出 .NET 异常"不能对 Null 值表达式调用方法"、按钮卡在"优化中..."的问题
  - 根因：PowerShell 5.1 中 `Timer` 事件回调对函数/事件内局部变量的解析在部分执行路径下失败，变量为 `$null` 导致 `.Stop()` 调用报错
  - 修复：所有定时器回调改用 `.GetNewClosure()` 显式闭包捕获变量；回调内 `try/catch` 兜底，无论是否异常都恢复按钮文字与可用状态
- **加固**：全局未处理异常捕获（`ThreadException` + `AppDomain.UnhandledException`），异常写入 `memory-tool-error.log`（与脚本同目录），不再弹出 .NET 异常对话框
- **防御**：内存读数 CIM/COM 返回空值时的全链路 null 兜底、快捷方式对象判空、进程命令行判空过滤
- **修复**：清理工作集跳过自身进程的逻辑改用 `if` 包裹，避免 `return`/`continue` 在 `ForEach-Object` 中导致后台常驻进程启动即退出的问题

- 关闭按钮改为始终可点（幂等清理）；开启/关闭/应用间隔后延迟刷新状态徽章；界面每 10 秒自动同步定时状态
